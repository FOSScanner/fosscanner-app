# Documentation screenshots

The README's document-workflow images are generated from the current
Flutter widgets with a synthetic document. They are **UI renders, not device
screenshots**, and do not establish native camera, OpenCV, OCR, or PDF output
quality.

| File | Screen |
| --- | --- |
| `ui-home-empty.png` | Initial document screen |
| `ui-home-pages.png` | Three-page document and compact export bar |
| `ui-home-pages-dark.png` | The same document in the dark theme |
| `ui-export-options.png` | Android searchable-text export options |
| `crop-full-image-fallback.png` | Full-image selection after detection fallback |
| `ui-adjust-appearance.png` | Numeric adjustments, Filters icon, and Add page |
| `ui-filters-panel.png` | Filter choices opened explicitly from the Filters icon |

## Reproduce

From the repository root, using Flutter **3.44.0 / Dart 3.12**:

```bash
flutter pub get
flutter test tool/render_readme_screenshots_test.dart
```

This is an explicit documentation task, outside `test/`, so normal
`flutter test` does not rewrite tracked PNGs. It renders at 390 × 844 logical
pixels, text scale 1, with 2× PNG output (780 × 1688). It loads Roboto and
Material Icons from the active Flutter SDK's cached material fonts; no fonts
or screenshots are downloaded by the renderer. Theme colors follow the app's
deep-purple Material 3 configuration.

The camera-picker capability is a test fixture. Draft persistence is disabled,
so no real scans are loaded or saved. The editor uses fixture operations that
return the sample unchanged: its thumbnails are not filter comparisons, and
its fallback is injected rather than produced by native edge detection. No
camera session, OCR operation, share sheet, browser launch, APK build, or device
installation is involved.

Review the output visually after generating it. Keep UI copy and alt text
aligned with the rendered source; do not edit controls into screenshots.

## Other images

`barcode-complete-url.png` and `barcode-review-large-text.png` are earlier
Flutter renders with synthetic barcode content and a placeholder camera
background. They are not regenerated by the document-workflow renderer.

The older `home-*.png`, `review-*.png`, and `adjustment-preview-retry.png`
images are retained as historical UI examples. They may not match the current
candidate's labels and are not used as its primary README screenshots.

No image in this directory should contain personal scans, OCR text, credentials,
or private file paths. Real-device acceptance results are tracked separately
from these illustrative renders.
